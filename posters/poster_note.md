- Linuxとは？
    - OS（オペレーティングシステム）の1つ
    - macOS、Windowsに並ぶ第3のOS
    - 現在はサーバーなどの目に見えない裏側で使われることが多い
    - しかし、近年ではデスクトップOSとしての活用も広がっている
        - https://gigazine.net/news/20260902-statcounter-os-market-share/
        - デスクトップOSとは
            - サーバーのようなCUI中心の環境と、普段私たちが使っているデスクトップ環境がある
            - // きっと一般層においてはデスクトップ環境という概念が薄いので、まずそこを意識させる必要がある
            - WindowsやmacOSではデスクトップ環境を自由に変更することはできない
            - しかしLinuxでは、ユーザーが好みの環境を自由に選ぶ権利がある
                - では具体的にどんなデスクトップがあるのか？ => Desktopへ
            - コンソールとGUIの変遷
                - 昔はコンソールに文字を入力するだけの操作が一般的だった
                - しかしMS-DOSや初期Macなど、現代につながるGUIの登場によって、グラフィカルかつ直感的にコンピューターを操作できるようになった
                - それでもなお、歴史的な名残だけでなく、圧倒的な強力さ・メリットがあるからこそ、コンソール（CLI）は現代でも第一線で使われ続けている
                    - ターミナルについて => Terminalへ
- Desktop
    - そもそもOSにはカーネルとユーザー空間がある
    - 実際にコンピューターを動かす中核部分と、それらと人間をつなぐインターフェース
    => そのインターフェースを担うのがデスクトップ環境 // と言えそう
    - 代表例
        - GNOME :: 直感的で、一貫性を重視した完成された操作体系
        - KDE :: 圧倒的なカスタマイズ性と機能美
        - Hyprland, niri :: 少し独特だが、慣れると手放せなくなるタイリング型ツール
    - 選んだデスクトップ環境によって、コンピューターの使い方やカスタマイズのしやすさが大きく変わる
    - 今回の体験会で触れるのは、高いカスタマイズ性を誇る「KDE Plasma」
        - GUIから手軽に設定を変更でき、画面効果（エフェクト）なども自由に楽しめるのが魅力
- Terminal
    - ハッカーの「黒い画面」の正体を解き明かす
    - なぜ文字だけで操作するのか？
        - そもそもコンピューターの操作は、すべて「コマンド」によって指示できる
            - 例: `mkdir` :: make directory（フォルダを作成する）
            - マインクラフトのコマンドなどと同じ仕組み
        - でも「エクスプローラーで右クリックしたり、Ctrl + Shift + N を押せば作れるのでは？」
        => CLIには、それを上回る大きなメリットがいくつもある
            - 1. 自動化の圧倒的なしやすさ
                - コマンドは「スクリプト」という形で1つのファイルにまとめ、一括実行できる
                    - 定型作業を機械に任せて自動化できるので非常に便利
                - 同じコマンドは（多くの場合）いつでも同じ挙動をするため、操作そのものをコピペして再現・共有できる
            - 2. コマンド同士の組み合わせによる柔軟な処理
                - あるコマンドの実行結果を次のコマンドへと渡すことで、リレーのような連続処理が可能
                - 例えば以下のコマンド：
                    - `ps` :: 現在動作中のプログラム（プロセス）を確認するコマンド。`ps aux` でシステム全体で稼働中のプログラムを一覧表示
                    - `rg` :: 入力されたテキストから特定の文字列を検索する。`rg chrome`
                    - // stdin, stdoutについては後で補足
                - これらをパイプで組み合わせると `ps aux | rg chrome`
                    - このコマンド1行で、「システム全体で動いているプログラムの中にchromeが含まれているか」を一瞬で確認できる
                    - 仕組み：
                        1. `ps aux` でプログラム一覧を出力
                        2. パイプ `|` が `ps aux` の出力を次の `rg chrome` コマンドへとそのまま流し込む
                        3. `rg chrome` は受け取った一覧の中から `chrome` を含む行だけを抽出して表示する
                    - パイプの素晴らしい点は、シンプルな単機能コマンドを組み合わせるだけで目的を達成でき、修正や応用も極めて容易なこと
            => CLIの世界には「単一の機能に特化した小さな道具を組み合わせ、大きな仕事を成し遂げる」というUNIX哲学が根付いている
    - ちなみにTUIという選択肢もある
        - 現代では、単なるコマンド実行だけでなく、ターミナルの文字表示だけでグラフィカルな画面操作を実現するツール（TUI）も盛んに使われている
        - 例: Neovim、lazygit、btopなど
