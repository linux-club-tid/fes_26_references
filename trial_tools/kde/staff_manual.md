# KDE体験 スタッフマニュアル

## 1. 体験の目的と所要時間

参加者にKDE Plasmaを自由に触ってもらい、「Linuxでは見た目や操作方法まで自分好みにカスタマイズできる」と実感してもらうことを目標とする。設定項目の暗記や完成度の採点は行わない。

- 基本コース: 約10分
- 追加チャレンジ: 5～10分
- 対象: マウスのクリック、右クリック、ドラッグ操作ができる人
- スタッフ配置: 体験PC 1～2台につき1人を目安とする

基本コースでは、壁紙とテーマの変更、パネルの調整、ウィジェットの配置を行う。体験時間や参加者の興味に応じて、画面効果（デスクトップ効果）も試してもらう。すべての項目を終わらせることよりも、参加者が気に入った項目をじっくり選んで楽しむことを優先する。

## 2. 当日までの準備

### 必要な環境

- KDE Plasma 6を日本語で利用できるLinux VM
- VirtualBoxを実行できる体験PC
- sudo権限を持たない体験専用ユーザー
- 参加者向けマニュアル `trial_tools/kde/manual.pdf`
- 復元確認済みの初期スナップショット
- トラブル時にすぐ切り替えられる予備PCまたは予備VM

VMでは、ネットワーク、共有フォルダー、共有クリップボード、ドラッグ＆ドロップ、USB機器の自動接続を無効化しておく。ホストPCやVM内には個人ファイルや保存されたアカウント情報、秘密情報を置かないこと。また、体験専用ユーザーには管理者権限（sudo権限）を与えない。

初期スナップショットは、次の状態を確認してから作成する。

1. 体験専用ユーザーで正常にログイン（または自動ログイン）できること。
2. 表示言語、キーボード配列、日時（タイムゾーン）が日本語環境になっていること。
3. 画面解像度やスケーリング（拡大率）が体験PCのディスプレイに合っていること。
4. 壁紙、グローバルテーマ、ウィジェット、画面効果などの選択肢があらかじめ用意・インストールされていること。
5. パネルが表示されており、アプリケーションメニューや「システム設定」を正常に開けること。
6. 参加者向けマニュアルが手元ですぐ読める位置に用意されていること。
7. 初期スナップショットへ復元した際、問題なく初期状態に戻ることを確認済みであること。

会場で使用するVM名とスナップショット名は、スタッフ全員が確認できる運営メモに明記しておく。復元先を推測や当てずっぽうで選んではならない。

### 開場前チェック

各体験PCで、以下の項目を事前に確認する。

1. ホストPCを電源に接続し、スリープ設定を無効化する。
2. VMを初期スナップショットへ復元して起動する。
3. KDE Plasmaのデスクトップが日本語で正常に表示されることを確認する。
4. マウスの右クリックやドラッグ、キーボード入力が正常に動作することを確認する。
5. システム設定を開き、「色とテーマ」と「デスクトップ効果」を表示できることを確認する。
6. デスクトップやパネルの編集モードを開き、問題なく閉じられることを確認する。
7. ウィジェットを1つ追加し、正常に削除できるか試す。
8. 参加者向けマニュアルの手順を最初から最後まで一通り通して試す。
9. 確認完了後、VMをもう一度初期スナップショットへ復元しておく。

あわせて、ネットワークに接続されていないことや、ホストPCとのファイル共有・クリップボード共有が無効化されていることも確認する。

## 3. 参加者への案内

参加者が着席したら、まず次のように案内する。

> この体験では、Linuxのデスクトップ画面を自分好みにカスタマイズしてみます。壁紙や色、画面下のパネルなどを自由に変えてみてください。体験用の環境なので、失敗しても全く問題ありません。困ったときはいつでも元に戻せますので、気軽に声をかけてくださいね。

続けて、以下の注意事項（禁止事項）のみを簡潔に伝える。

- 個人情報を入力しないこと。
- 自分のアカウントにログインしないこと。
- ファイルを削除しないこと。
- 新しいテーマやウィジェット、ソフトウェアなどを外部からダウンロードしないこと。
- 設定中にパスワードを求められた場合は、入力せずにスタッフを呼ぶこと。

導入として、まずは「デスクトップの何もない場所を右クリックしてみましょう」と案内する。その後は参加者向けマニュアルを見ながら進めてもらい、スタッフが操作を先回りして指示しすぎないように見守る。完成例を唯一の「正解」として押しつけず、「どんな色が好きですか？」「パネルはどこにあると使いやすそうですか？」のように、参加者自身の好みの選択を促す。

## 4. 体験の進め方

| 段階 | 参加者が行うこと | スタッフが確認すること |
| --- | --- | --- |
| 導入 | デスクトップを右クリックする | メニューが正常に開き、選択できるか確認 |
| 1A | 壁紙を選んで適用する | 文字やアイコンが見えづらくなっていないか確認 |
| 1B | グローバルテーマまたは配色を変える | 変更の確認ダイアログを理解できているか確認し、必要なら「レイアウト変更」を外すよう助言する |
| 2 | パネルの位置、太さ、長さなどを変える | パネルを見失わずに操作でき、編集モードを正常に終了できるか確認 |
| 3A | ウィジェットを追加して配置する | ウィジェットが追加できているか確認（必要に応じて削除方法も案内） |
| 3B | 画面効果を有効にして試す | 効果が反映され、動作が重くなっていないか確認 |
| 完成 | 気に入った点をスタッフへ見せる | 工夫した点や気に入ったところを簡単に聞き、体験を締めくくる |

混雑時は、壁紙・テーマ・パネルまでを基本コースとして終了してもよい。また、参加者がひとつのカスタマイズを気に入ってじっくり試している場合も、無理に次のステップへ急がせる必要はない。

### 案内する設定経路

- 壁紙: デスクトップを右クリック →「デスクトップと壁紙を設定…」
- テーマと配色: アプリケーションメニュー → システム設定 → 色とテーマ
- パネル: パネルの何もない場所を右クリック →「パネル設定を表示」
- ウィジェット: パネルを右クリック →「パネル設定を表示」→「ウィジェットを追加」
- 画面効果: システム設定 → ウィンドウの管理 → デスクトップ効果

表示名が少し異なる場合は、システム設定の検索欄で「壁紙」「色」「効果」などのキーワードで検索する。

### 声かけの順序

参加者の手が止まってしまったときは、以下の順序でサポートする。

1. 「今はどの部分を変えてみたいですか？」と、やりたいことを確認する。
2. マニュアルの該当箇所や画面上の項目を指し示す。
3. 「クリック」「右クリック」「ドラッグ」のうち、必要な操作を1つだけ伝える。
4. それでも操作が難しい場合は、参加者の了承を得た上で、スタッフが一度だけ操作をお手本として実演する。

スタッフが操作を代行する場合でも、何を変更しようとしているのか口頭で説明し、最後の選択や「適用」ボタンのクリックはできるだけ参加者自身に行ってもらう。

## 5. サポートの基準

### 操作に慣れていない参加者

- 一度に案内する操作は1つだけにする。
- 右クリックする場所やドラッグ先を指で示す。
- ダブルクリックとシングルクリックを混同している場合は、必要な操作だけを伝える。
- 画面の文字が小さくて読みづらそうなら、体験を続ける前にスタッフが表示倍率（スケーリング）を調整する。
- パネルやウィジェットの細かい調整は無理に行わず、省略してもよい。

### 早く終わった参加者

時間や興味に応じて、以下の中から1つ案内してみる。

- 明るい配色と暗い配色で、壁紙の見え方の違いを比べる。
- パネルを上下左右へ動かしてみて、使いやすさを比べる。
- ウィンドウを開いた状態で、パネルの自動非表示を試す。
- 「揺れるウィンドウ」「マジックランプ」「概要」などのデスクトップ効果を試す。
- `Meta + W`、`Alt + Tab`、`Meta + 矢印` などのショートカットキーでウィンドウ操作を試す。

ソフトウェアや追加テーマの新規インストール、オンラインアカウントへの接続、教材にないシステム管理操作などは案内しない。

### 体験の締め

カスタマイズが完成したら、「どこが一番気に入りましたか？」と参加者に感想を尋ねてみる。

> 壁紙だけでなく、パネルの位置やウィンドウの動きまでガラリと変えられましたね！ Linuxでは、こうした画面全体の見た目や使い勝手も、自分にぴったりのものを自由に選んでカスタマイズできます。

記念に画面を撮影する場合は、参加者本人や私物が写り込まないよう十分配慮し、撮影の可否および利用目的について必ず事前に本人の同意を得ること。

## 6. 次の参加者への初期化

参加者が交代するたびに、必ずVMを初期スナップショットへ復元する。KDEの設定を手作業で戻そうとすると変更の見落としが発生しやすいため、通常の初期化手順としては行わないこと。

1. 体験が終了したことを確認する。
2. 開いている設定画面やアプリケーションをすべて閉じる。
3. KDEのメニューから通常通りシャットダウンを行い、VMが完全に停止するまで待つ。
4. VirtualBoxの管理画面で対象のVM名を確認する。
5. 事前に指定されている「初期スナップショット」へ復元する。
6. VMを起動し、デスクトップ、パネル、壁紙などがすべて初期状態に戻っていることを確認する。
7. 参加者向けマニュアルを最初のページに戻し、次の参加者を席へ案内する。

混雑している場合であっても、前の参加者の設定が残った状態で次の体験を始めてはならない。復元に時間がかかる場合は、待たせずに予備VMまたは予備PCへ案内する。

イベント開催中に、スナップショットを新規作成・削除・上書きしてはならない。また、残しておきたい作品がある場合でも、運営責任者の判断や許可なくVM外部やホストPCへデータを書き出して保存しないこと。

## 7. トラブル対応

### パネルが見つからない

1. 画面の上下左右すべての端へマウスカーソルを近づけ、自動非表示になっていないか確認する。
2. `Esc` を数回押して、開いている編集モードやメニューを閉じる。
3. デスクトップを右クリックし、編集モードからパネルの状態を確認する。
4. 誤ってパネルが削除され、短時間で復元できない場合は、その回を切り上げてスナップショットから復元する。

「パネルまで自由に変えられることが体験できましたね！ すぐ元の状態に戻せますのでご安心ください」のように伝え、決して参加者の操作ミスを責めないこと。

### ウィジェットを消せない

編集モードを開き、対象のウィジェットを選択して削除する。右クリックメニューから削除できる場合もある。消し方が分からなければ無理に直そうとせず、そのまま体験を続けて終了後にスナップショットで復元する。

### 画面表示が崩れた、文字が読めない

- グローバルテーマを変えた直後なら、別の標準テーマまたは配色へ変更してみる。
- パネルやウィンドウが操作できる状態なら、参加者の体験を止めずに別の項目へ案内する。
- 操作自体が難しい状態になってしまったら、VMを通常終了して初期スナップショットから復元する。

### 画面効果で動作が重い、表示が乱れる

直前に有効化した効果をオフにして「適用」をクリックする。それでも改善しない場合はVMをシャットダウンし、参加者を予備PCへ案内した上で初期スナップショットから復元する。ホストPCを強制終了する必要がある場合は、事前に運営責任者へ連絡する。

### 設定変更でパスワードを求められた

パスワードは絶対に入力しないこと。その操作をキャンセルし、今回の体験範囲外である旨を説明する。参加者に管理者パスワードを教えてはならない。

### VMが固まった、起動しない

1. 30秒ほど待ち、マウスカーソルやキーボード入力への反応があるか確認する。
2. VirtualBoxの動作状況と画面のエラー表示を記録する。
3. 参加者を速やかに予備PCへ案内する。
4. 通常終了できる場合はシャットダウンし、初期スナップショットへ復元する。
5. 強制停止が必要な場合は、運営責任者の確認を得てから実施する。

参加者を待たせたまま目の前で長時間の原因調査を行ったり、管理者権限で修復やパッケージ更新を試みたりしないこと。

## 8. スタッフ用クイックリファレンス

| 状況 | 対応 |
| --- | --- |
| 設定項目が見つからない | システム設定の検索欄でキーワード検索 |
| メニューや編集画面を閉じたい | `Esc` |
| アプリケーションメニューを開く | `Meta` |
| ウィンドウ一覧を表示 | `Meta + W` |
| ウィンドウを切り替える | `Alt + Tab` |
| ウィンドウを画面半分へ配置 | `Meta + 矢印` |
| アプリや設定を検索する | `Alt + F2` |
| パネルが見当たらない | 画面の四辺へカーソルを動かす |
| 状態を完全に戻す | VM停止 → 指定スナップショットへ復元 → 再起動 |

この体験では、設定を完璧に仕上げることよりも、参加者自身が選んで画面の変化を楽しめたという体験を何より大切にする。
