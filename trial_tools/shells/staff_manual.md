# shell体験 スタッフマニュアル

## 1. 体験の目的と所要時間

参加者が「黒い画面は怖いもの」ではなく、文字でコンピューターへ指示できる道具だと感じることを目標にする。コマンドの暗記や用語の試験は行わない。

- 基本コース（1～3問）: 5～8分
- 発展コース（4～5問）: 追加で3～7分
- 対象: アルファベットと記号をキーボード入力できる人
- スタッフ配置: 体験PC 1～2台につき1人を目安とする

題材は「迷子のペンギンTuxを目撃記録から探す」。画面左に問題、右に本物のbashを表示する。参加者は右側でコマンドを実行し、見つけた答えを `answer 答え` で送信する。paneの移動操作は不要。

## 2. 当日までの準備

### 必要な環境

- LinuxまたはLinux VM
- Python 3.10以降
- bash
- tmux
- sudo権限を持たない体験専用ユーザー `trial`
- 日本語を表示できる端末と等幅フォント

VMではネットワーク、共有フォルダー、共有クリップボード、ドラッグ＆ドロップを無効にする。WSL2を使う場合はWindowsドライブの自動マウントとWindows interopも無効にする。体験環境に個人ファイルや秘密情報を置かない。

### 開場前チェック

1. `trial` ユーザーでログインする。
2. 端末を最大化し、文字が離れた位置から読める大きさにする。
3. `trial_tools/shells/new.py` を実行する。
4. 左に問題、右に `trial$` が表示されることを確認する。
5. スタッフ自身で全5問を通し、下表どおり進むことを確認する。
6. `Ctrl+B` を押して離し、`Shift+R`、`y` の順で終了する。
7. もう一度 `new.py` を実行し、最初の問題に戻ることを確認する。

起動コマンド:

```sh
cd trial_tools/shells
./new.py
```

## 3. 参加者への案内

最初は次のように説明する。

> 右側の黒い画面は、文字でコンピューターにお願いする場所です。左側の問題を見ながら操作します。間違えても体験専用なので大丈夫です。まず `ls` と入力してEnterを押してください。

あわせて、次の3点だけ伝える。

- 画面の `trial$` は入力しない。その右側に入力する。
- 入力途中でTabを押すと、ファイル名を補完できる。
- 答えが分かったら `answer 答え` と入力する。

最初からコマンドを読み上げ続けず、参加者が左側の問題を読んで試す時間を取る。詰まった場合は「左側に何を調べると書いてありますか」「使えそうなファイルはどれですか」の順に声をかけ、それでも難しければ画面のヒントや正解コマンドを案内する。

## 4. 問題と回答一覧

| 問題 | ねらい | 想定コマンド | 送信する答え |
| --- | --- | --- | --- |
| 1. ファイルを見つける | 一覧表示 | `ls` | `answer welcome.txt` |
| 2. ファイルを読む | 内容表示 | `cat welcome.txt` | `answer Tux` |
| 3. 必要な行を探す | 文字列検索 | `grep Tux members.txt` | `answer guide` |
| 4. 行番号も表示する | オプション | `grep -n Tux sightings.txt` | `answer PC Room` |
| 5. 組み合わせる | パイプと行数 | `grep Tux sightings.txt \| wc -l` | `answer 4` |

大文字・小文字、全角・半角、前後の空白は可能な範囲で自動的に吸収される。想定コマンド以外で答えへ到達しても正解とする。

3問目の後は基本コースの完了画面になる。混雑時や疲れている参加者には `answer finish`、余裕があれば `answer next` を入力してもらう。

## 5. サポートの基準

### 入力に慣れていない参加者

- 一度に伝える操作は1つだけにする。
- ファイル名はTab補完を使ってもらう。
- 記号 `|` はキーボード上の位置を指し示してよい。
- スタッフが代わりに入力する場合も、実行前に参加者へ内容を説明する。

### 早く終わった参加者

次の自由課題から1つだけ案内する。

- `grep Tux sightings.txt` と `grep -n Tux sightings.txt` の違いを見る。
- `grep Mochi sightings.txt | wc -l` で別の名前を数える。
- 上矢印キーで以前のコマンドを呼び出し、一部だけ書き換える。

教材ディレクトリ外を探索させる課題、ソフトウェアのインストール、ネットワークを使う課題は案内しない。

### 説明の締め

> `cat`、`grep`、`wc` はそれぞれ小さな仕事をする道具です。最後は `|` で道具をつなぎました。LinuxのCLIでは、このように小さな道具を組み合わせて、自分に必要な操作を作れます。

## 6. 次の参加者への初期化

1. 現在の参加者が完了したことを確認する。
2. `Ctrl+B` を押して離す。
3. `Shift+R` を押す。
4. 確認表示で `y` を押す。
5. 端末で `./new.py` を実行する。
6. 右側のpaneが選択され、問題1が表示されていることを確認する。

各回は新しい作業ディレクトリで始まるため、前の参加者が変更した内容は次の回へ引き継がれない。古い作業ディレクトリは閉場後に管理者がまとめて削除する。当日の判断で広いパスを削除しない。

## 7. トラブル対応

### コマンドが動かない

- `command not found`: スペルと半角英字を確認する。
- `No such file or directory`: ファイル名を `ls` で確認し、Tab補完を試す。
- 画面が止まった: `Ctrl+C` を1回押す。
- 文字が大量に流れた: `Ctrl+C` を押してから `clear` を実行する。
- `answer` に答えを付け忘れた: 使用例が表示されるので、もう一度入力する。

### 左側の問題が進まない

1. 右側に「左側へ答えを送りました」と出たか確認する。
2. 答え一覧と照合する。
3. 数秒待っても変わらなければ、その回を終了して `./new.py` で作り直す。

### paneやshellを閉じてしまった

その回を終了し、新しいセッションを起動する。参加者の操作を責めず、「体験用なので、すぐ最初から作り直せます」と案内する。

### `new.py` が起動しない

- `tmuxが見つかりません`: tmuxの導入を担当者へ依頼する。
- `教材ファイルがありません`: `new.py` だけを別の場所へ移動していないか確認する。
- tmux関連のエラー: `tmux list-sessions` の結果と画面のエラーをコアスタッフへ伝える。

原因調査に時間をかけすぎず、予備PCへ案内する。参加者の前で `sudo` を使った復旧や設定変更は行わない。

## 8. スタッフが覚える操作

| 操作 | キーまたはコマンド |
| --- | --- |
| 体験を起動 | `./new.py` |
| 実行中のコマンドを止める | `Ctrl+C` |
| 画面を整理する | `clear` |
| 体験を終了 | `Ctrl+B` → `Shift+R` → `y` |
| tmuxセッション一覧 | `tmux list-sessions` |

参加者の入力内容は採点しない。正解へ至る方法より、「自分でファイルを調べ、必要な情報を取り出せた」という体験を優先する。
